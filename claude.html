claude

Use Claude models through your own Claude Code installation and sign-in, with the Claude Agent SDK. 
from fastcore.test import test_eq, test_fail

The wire

A turn either sends a message to a live Claude Code session or resumes a filed transcript with one query call. rishi calls the system prompt the briefing. It goes to Claude Code through Claude Code’s own system-prompt option.

By default, your tools travel as tags in the prompt. A managed MCP policy cannot remove them. Pass mcp_servers when Claude Code must reach an MCP server itself. Those tools run on Claude Code’s side, outside rishi’s approval, budget and result-length limits. rishi reports their calls in Resp.channels['server_tools'].

These defaults keep the backend working on locked-down machines:

  • strict_mcp_config is off. Enterprise configurations reject that flag.
  • api_key=False blanks ANTHROPIC_API_KEY in the subprocess environment. The session then bills your subscription, not the API. api_key=True leaves the variable as it is.
  • max_buffer sets the limit on Claude Code’s output. The SDK rejects output that exceeds the configured limit instead of truncating it.
limit bytes
SDK default 1 MiB (1048576)
MAX_BUFFER, the rishi default for max_buffer 10 MiB (10485760)

The constants below are pinned model ids. claude_model accepts the short keys of CLAUDE_MODELS, such as 'opus5'. It passes the CLI’s own aliases (opus, sonnet, haiku, fable) through unchanged. Each alias follows the newest model of its tier on your plan. With no model, a chat uses opus5, which is claude-opus-5.

norm_claude converts Claude Code’s result to a Resp. A failed turn raises ClaudeError. ClaudeError carries the HTTP status when one can be found, and a caller can use it to decide whether to retry. A cancelled turn is not an error. The reply is whatever arrived before the cancel.

claude_version asks the binary for its version and gives it /dev/null as stdin. Claude Code is a Node program. A Node program that shares the caller’s terminal can leave the terminal non-blocking.

One event loop

The SDK’s ClaudeSDKClient keeps a background task group running from connect to disconnect. Every call on the client must run on the event loop that created it. rishi’s code is synchronous. It uses fastcore.aio.run_sync and Urai’s sync_iter, which both run coroutines on fastcore’s one shared background event loop.

ClaudeChat

def ClaudeChat(
    model:NoneType=None, *, runtime:NoneType=None, model_path:NoneType=None, opts:NoneType=None,
    permission_mode:str='auto', # Claude Code's gate on its *own* tools. Yours are rishi's
    claude_tools:NoneType=None, # Claude Code's own tools, allowlisted. None -> none at all when this chat carries tools, its default set when it carries none
    claude_disallowed:tuple=('Bash', 'Write', 'Edit', 'NotebookEdit'), # Claude Code tools it may never use
    claude_server_tools:tuple=(), # its web tools, which run on its side and never reach rishi's loop
    mcp_servers:NoneType=None, # MCP servers to declare. None -> none at all. See `The wire`
    mcp_tools:NoneType=None, # which of their tools to allow. None -> every tool of every server named
    strict_mcp_config:bool=False, # refused outright where an enterprise MCP config exists
    workspace:NoneType=None, # directory Claude Code works in. None -> `CLAUDE_WORK_DIR`. See `_cwd`
    fallback:NoneType=None, # model, or models tried in order, for when this one is overloaded or retired
    cleanup:bool=True, # remove the transcripts this chat filed when it closes. See `prune_sessions`
    bare:bool=True, # answer as a model: no CLAUDE.md, skills, plugins or hooks
    stateful:bool=True, # keep one Claude Code session per chat. See `_connect`
    transcript:bool=True, # file the conversation as records rather than prose. See `_file_sess`
    api_key:bool=False, # False blanks `ANTHROPIC_API_KEY` in the subprocess; True lets it through. See `_opts`
    max_buffer:int=10485760, # the SDK's stdout cap, in bytes
    bin:str='claude', settings:NoneType=None,
    timeout:int=240, # seconds of silence before the turn is ended and tried once more. See `Silence`
    on_stall:NoneType=None, # called with a status note when that happens. None -> `warnings.warn`
    timeout_hint:NoneType=None, # how a caller raises `timeout`, named in the error. None -> `ClaudeChat(timeout=SECONDS)`
    **kw
):

A Chat that drives your Claude Code installation through the Claude Agent SDK.

Options

Claude Code has tools of its own, such as Bash and Edit. These rules decide which of them a chat can use:

  • A chat that carries rishi tools switches all Claude Code tools off. Your tools are the only ones Claude can call.
  • A chat with no rishi tools keeps Claude Code’s default set, minus claude_disallowed. By default claude_disallowed holds Bash, Write, Edit and NotebookEdit.
  • claude_tools=[] switches all Claude Code tools off and gives plain completions.
  • bare=True, the default, stops Claude Code from loading project instructions (CLAUDE.md), skills, plugins and hooks. It does not restrict tools.

tool_mode='native' sends rishi’s tools through an in-process MCP server, not through the prompt. See Native tool calls.

claude_server_tools switches on Claude Code’s web tools, WebSearch and WebFetch. They run on Claude Code’s side.

fallback names a model, or a list of models tried in order. Claude Code uses them when the chosen model is overloaded or retired.

set_model switches the model of a live session without rebuilding the history.

effort sets the reasoning effort: low, medium, high, xhigh or max. It is the only generation setting that Claude Code takes. The chat ignores temperature, token limits and similar options.

When the effort of a call differs from the effort the live session opened with, the chat reconnects the session and resumes it from hist. A call with no effort runs at the chat’s own effort and reconnects in the same way.

Pictures and documents

Claude Code takes Anthropic content blocks. rishi converts its OpenAI-shaped history with aidialog and fastllm. An image becomes an image block. A PDF becomes a document block. A live session and a filed transcript both carry these blocks.

With stateful=False, transcript=False, the chat flattens the history into one text prompt. A text prompt cannot hold an image, so the chat refuses media. Claude Code takes no audio on any path.

Transcript records

Claude Code resumes a session from a JSONL transcript at ~/.claude/projects/<cwd>/<id>.jsonl. anth_msgs converts rishi’s history into Anthropic messages. llmsurgery.ant writes them as transcript records. anth_blocks keeps images and documents as typed blocks.

The chat files tool calls in the form that the session uses.

On the default tags channel, tag_calls files a call as <tool_call> text and files its result as prose. render_prompt sends them in the same form in a live session. Filing them as native tool_use blocks failed. A resumed session saw tools that the options no longer declared, and it ended its next turn after one sentence.

On the native channel, the chat files calls and results as tool_use and tool_result blocks. tu_id rewrites each id into Anthropic’s toolu_ form so that every pair matches. A tool that returned nothing is filed as (no output). The API rejects empty text blocks.

The chat always files assistant content as a list of blocks. Claude Code 2.1.238 calls .some() on it, and a plain string crashes it.

A session id is a hash of the messages plus a random value that is unique to each chat. Refiling the same chat gives the same id. Two chats that hold the same conversation get different files, and neither deletes the other’s file during cleanup.

A chat removes the transcripts it filed when it closes, unless cleanup=False. prune_sessions clears old transcripts that remain. Each record carries the version that the installed claude --version reports.

Two settings decide how the conversation travels:

  • stateful=True, the default, keeps one Claude Code process for the chat. It sends tool results mid-turn as text.
  • stateful=False starts a fresh query each turn and refiles the whole history as typed records. Adding transcript=False sends the history as one flattened text prompt, which cannot carry media.

Session watermark

During a tool turn, the chat appends Claude’s reply and then the tool results to hist. The live session already holds its own reply. Sending the reply back would make Claude read its own words as new input.

_sent marks how much of hist the session has seen. Each request sends only what comes after that mark. When a chat connects by resuming a filed transcript, _sent starts at the length of the filed history. The first request then sends only the new user message.

set_opts changes the options the next Claude Code connect gets, such as max_budget_usd. A value set to None is dropped. A stateful chat keeps one Claude Code session, and Claude Code counts a budget over that session, so a changed value ends the open session; the next call resumes it from hist with the new options.

Native tool calls

With tool_mode='native', rishi’s tools reach Claude as MCP tools, not as prompt text. The chat declares an in-process MCP server named rishi (RISHI_MCP). The server holds one tool per toolspec, with the toolspec’s JSON schema and descriptions. Only those tools are allowed, as mcp__rishi__NAME. Claude Code’s own tools stay off. The schemas leave the system prompt.

In this mode Claude Code runs the tool loop itself. One model step can hold several calls. Each call passes through the same pieces of Urai’s loop as a tagged call:

  • _approve1 applies the approval gate, the step budget and before_tool_calls.
  • call_tool runs the tool.
  • _record_tool truncates the result to tool_max_len and applies after_tool_calls.

The chat writes the call and its result to hist. Transcripts, resumes and callbacks see them as they see tagged calls.

Calls run one at a time. Each call runs in a worker thread, inside a copy of the context of the thread that started the step. Context variables therefore reach the tool and the approver. The silence timer waits while a tool runs.

A refused call, a spent budget and a cancelled turn each answer Claude with the reason. A spent budget also interrupts the live session. A turn that ran a native tool is never tried again after a stall.

A machine with an enterprise MCP configuration refuses every MCP server a program declares. There the chat raises ClaudeMcpRefused, a ClaudeError that carries Claude Code’s own message. The caller can then switch to tool_mode='tags'. A tool name longer than MCP_NAME_MAX, 64 characters with the prefix, raises ValueError.

The two steps the tool loop drives

Urai’s tool loop asks a backend for one model step at a time, either whole (_model_step) or streamed (_stream_step), and runs any tool calls in between. cancel stops a turn and also tells a live session to stop generating. set_model switches the model, on a live session too. token_count returns what the live session last reported holding, or an estimate before it has reported, and never waits on the session.

Silence

Claude Code streams token deltas, so a working turn is never quiet for long. A turn that sends nothing at all, not even a stream event, for timeout seconds (240 by default) is stuck. _drain closes the stream, which ends the SDK’s query and its subprocess, and raises ClaudeStall. _with_retry then disconnects a live session, passes a status note to on_stall, and tries the turn once more.

What the retry sends depends on what was already shown:

  • Nothing yet, or only thinking: the same turn again, from the same filed conversation. The thinking may show twice.
  • Text: that text is not sent again. It is filed as the reply so far, and a fresh query asks Claude Code to finish it with STALL_PROMPT. Only the continuation streams, and the turn’s result is the shown text plus the continuation.
  • A call to one of Claude Code’s own tools: no retry. A replay would run the tool again. The stall is raised.
  • A native tool call: the timer waits while the tool runs. After one has run, a stall is raised and not retried.
  • A whole tool call in the text: the turn ends there with that text, as it would have, and a live session reconnects on the next turn.

A failure while connecting gets the same one retry, with a status note to on_stall. On a live session, that is client.connect() failing with a CLIConnectionError or not finishing in timeout seconds. On a query, it is the same error, or Claude Code’s initialize request timing out, before any message arrives. Nothing has run at that point, so nothing is replayed. A missing claude binary (CLINotFoundError), a refusal of rishi’s MCP server, and any other error are raised at once. Another try would fail the same way.

Each wire call has one retry, shared by a failed connect, a stall and a session that died before it said anything. After a connect is retried, a stall is raised, not retried. A failed connect on the retry that follows a stall raises the connect error. A cancelled turn is never retried.

If the retry goes silent too, ClaudeStall names the limit and timeout_hint, which says how the caller raises it. The stalled attempt sent no result, so its tokens and cost are not counted. _oneshot is not retried.

c = ClaudeChat(stateful=False, transcript=False)
stop = {'is_error': True, 'subtype': 'error_max_budget_usd', 'cost': 8.4, 'usage': {'input_tokens': 10, 'output_tokens': 5}}
c._events = lambda: iter([('result', stop)])
test_fail(c._model_step, contains='budget')
test_eq(round(c.use.cost, 2), 8.4)   # the stopped run was paid for, so `use` counts it, as a caller's turn total does
c._events = lambda: iter([('result', stop)])
test_fail(lambda: list(c._stream_step()), contains='budget')
test_eq(round(c.use.cost, 2), 16.8)

Pass mcp_servers when Claude Code must reach an MCP server itself. Every tool of each named server is allowed unless mcp_tools narrows the list. These tools run inside Claude Code, outside rishi’s tool loop. rishi reports their calls in Resp.channels['server_tools'], not in tool_calls. Nothing waits on rishi to answer them.

A tagged tool round trip

Claude receives rishi’s tool schemas in the system prompt. When it writes a tagged call, norm_claude converts the tag to an ordinary tool call. Urai’s tool loop runs the Python function and records the result. Claude then writes the final reply. This test scripts the two replies from Claude. The parser, the tool loop, the function call and the history are real.

Against Claude Code with tagged tools

This cell uses the default live session. Claude receives the tool schema through _sp() and writes a tagged call. rishi parses the tag, runs the Python function and sends the result back to the same Claude Code session. The cell needs a signed-in Claude Code installation. The test run skips it.

from rishi.claude import ClaudeChat
from urai import resp_text
live_tag_calls = []
def live_tag_add(a: int, b: int) -> int:
    "Add two integers and record the call."
    live_tag_calls.append((a, b))
    return a + b

live_tag = ClaudeChat('haiku', tools=[live_tag_add], default_cbs=False)
live_tag_reply = live_tag('Use live_tag_add once with a=2 and b=3. Then answer with only the result.')
assert live_tag_calls == [(2, 3)]
assert '5' in resp_text(live_tag_reply)
assert [m['role'] for m in live_tag.hist] == ['user', 'assistant', 'tool', 'assistant']
assert live_tag.hist[2]['content'] == '5'
assert live_tag.hist[2]['tool_call_id'] == live_tag.hist[1]['tool_calls'][0]['id']
assert 'server_tools' not in (live_tag_reply.get('channels') or {})
live_tag.close()

MCP events from the SDK

MCP tools run inside Claude Code, not in Urai’s tool loop. _sdk_events picks up the SDK’s ToolUseBlock for each such call and passes it through to the final result. This test replaces the SDK’s query iterator, so no MCP server runs and Claude is not contacted.

A reply that goes on past its own tool call

A model can write a tool call and keep going in the same response as though the call had been answered. It writes more calls, then findings it never saw. Claude Code’s result holds only the last text block. Without a guard, the calls were lost and the invented findings reached the caller as the answer.

_drain stops at the first text block that holds a call. rishi shows and keeps nothing after that block. The turn’s text is what came before the stop. The call runs, and its real result comes back.

Against Claude Code and a local MCP server

This cell gives Claude Code a real MCP server running inside the Python process. Claude chooses and runs the MCP tool. The assertions check that the Python handler ran and that rishi received Claude Code’s report of the call. The cell needs a signed-in Claude Code installation. The test run skips it.

from claude_agent_sdk import create_sdk_mcp_server, tool

mcp_calls = []
@tool('add', 'Add two integers.', {'a': int, 'b': int})
async def mcp_add(args):
    mcp_calls.append((args['a'], args['b']))
    return {'content': [{'type': 'text', 'text': str(args['a'] + args['b'])}]}

calc = create_sdk_mcp_server('calc', tools=[mcp_add])
live_mcp = ClaudeChat('haiku', mcp_servers={'calc': calc}, mcp_tools=['mcp__calc__add'],
                      stateful=False, transcript=False, default_cbs=False)
live_reply = live_mcp('Use the calc add tool once with a=2 and b=3. Then answer with only the result.')
assert mcp_calls == [(2, 3)]
assert resp_text(live_reply).strip() == '5'
assert [x['name'] for x in live_reply['channels']['server_tools']] == ['mcp__calc__add']
live_mcp.close()
