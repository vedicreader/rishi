Where the daemon is

OLLAMA_HOST takes a bare port, a host:port, or a full URL. One variable both configures the daemon and finds it. ollama_url accepts all three forms.

A request to a loopback daemon must not go through an HTTP proxy. httpx reads $HTTPS_PROXY from the environment by default. In a sandbox, that setting sends 127.0.0.1 to a proxy with no route back. is_local decides whether a client trusts the environment.

Model ids

Ollama names models family:tag. It also serves any GGUF repo on the HuggingFace Hub under an hf.co/ prefix. ollama_model maps rishi’s ids to these names, with quant as the tag. The Qwen/Qwen3-4B-GGUF constant that rishi.llama uses works here unchanged.

A local .gguf file has no address in Ollama’s store. Importing one takes a blob upload and an /api/create call. ollama_model raises a ValueError that says so. It does not send the path to the daemon.

The wire

OllamaClient wraps the HTTP endpoints that rishi uses. /api/chat talks to a model. The management endpoints list the local store, pull missing models, and name the models in memory.

A refusal carries a JSON error field. OllamaError repeats that message.

/api/pull and a streamed /api/chat both answer in newline-delimited JSON. One stream method serves both. An error can also arrive mid-stream, after a 200 status. The iterator checks for it.

Installing Ollama

Ollama publishes one release archive per platform. Installing from the archive needs no root access and no package manager. The published one-liner installs into /usr. The archive extracts to any folder. rishi installs its own copy under ~/.cache/rishi/ollama and leaves the system alone.

ollama_bin looks for a binary in this order:

  1. $OLLAMA_BIN.
  2. rishi’s own install.
  3. ollama on $PATH, unless you pass system=False.

rishi downloads and installs Ollama only when none of these exists.

Linux archives use zstd. Python 3.14 and later reads zstd from the standard library. Earlier versions need zstandard, which rishi[ollama] installs. The macOS archive is gzip, and the Windows archive is a zip.

Running the daemon

OllamaServer starts ollama serve and waits for it to answer. It installs Ollama first if the machine has none.

Ollama sets some options per process, not per request. OllamaServer takes these options as constructor arguments:

Argument Environment variable Sets
models OLLAMA_MODELS the model store
n_ctx OLLAMA_CONTEXT_LENGTH the default context length
keep_alive OLLAMA_KEEP_ALIVE how long a model stays resident
flash_attn OLLAMA_FLASH_ATTENTION flash attention
kv_cache_type OLLAMA_KV_CACHE_TYPE KV cache quantization
num_parallel OLLAMA_NUM_PARALLEL parallel requests
max_loaded OLLAMA_MAX_LOADED_MODELS models loaded at once

rishi does not restart or reconfigure a daemon that already listens at the address. That server belongs to someone else.

rishi stops a daemon that it started when the interpreter exits. A notebook leaves no daemon running. The daemon gets /dev/null as stdin, so it never shares the caller’s terminal. It runs in its own session, so a Ctrl-C sent to the parent does not kill it.

Messages

Ollama’s message format is OpenAI’s, with two differences:

  • Images go in a sibling images list of bare base64. They do not go in content parts.
  • Thinking has its own thinking field. It does not use <think> tags in the text.

to_ollama_msg converts rishi’s canonical history to this format. It also carries assistant thinking out to the daemon. A resumed conversation keeps its thinking.

Images go out on every turn. They do not collapse to a placeholder. remote behaves the same way, and llama does not. The daemon holds the KV cache. A repeated image costs a prefix match, not a re-encode.

Audio has no place in this format. rishi.llama (mtmd) and rishi.mlx both take audio. The error says so and does not drop the clip.

OllamaChat

The tool loop, approval, budget, callbacks and context handling come from Urai, as on every backend. OllamaChat adds the request and the daemon that receives it.

think is a field of the request. It is not a switch in the system prompt. It takes True, False, or a level string such as 'low' or 'high'. The chat sends a level string unchanged. A model that cannot think refuses the field. The chat then retries once without the field and stops sending it.

These options map to Ollama request fields:

  • ctx, also accepted as the rishi.llama name n_ctx, goes out as num_ctx.
  • n_gpu_layers goes out as num_gpu.
  • options= takes anything else that Ollama’s sampler accepts.
  • structured uses Ollama’s format field. The schema constrains the reply. The prompt does not only ask for it.
  • keep_alive sets how long the daemon keeps the model loaded after a turn. unload() drops the model at once.

With pull=True, the default, the chat downloads a missing model when you build it. The llama backend does the same for a missing GGUF.

ctx_limit is the window that the chat assumes. It equals ctx when you set one. Otherwise it is $OLLAMA_CONTEXT_LENGTH from the environment of the Python process, or 4096 tokens when that variable is unset. The model’s training length does not matter. Urai’s pct_full and SlidingWindowCallback depend on this value. A daemon that someone else started with a different context length makes ctx_limit wrong. Pass ctx in that case.

When no daemon answers, or the model is not in its store, ollama_caps returns None. model_caps then uses Urai’s default, which accepts text input only.

What this backend does not do

This backend does not support the following:

  • Audio. Ollama’s chat API carries images but not audio. rishi.llama and rishi.mlx take audio.
  • A saved KV cache. rishi.llama and rishi.mlx write their cache to disk and read it back. Ollama keeps its cache inside the daemon and offers no handle on it. use.cached_tokens reads zero even while the daemon reuses the prefix.
  • Exact token counts before a turn. Ollama has no tokenizer endpoint. Counts before a turn are estimates. The real count arrives with the reply, in use.
  • Local .gguf paths. The chat refuses them, because Ollama serves only models in its own store. Use runtime='llama' for a file.
  • A broker. LlamaBroker exists because one Llama belongs to one process. The Ollama daemon already serves many clients. Size it with OLLAMA_NUM_PARALLEL and OLLAMA_MAX_LOADED_MODELS.
