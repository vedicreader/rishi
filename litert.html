litert

Run Google’s .litertlm model builds, such as Gemma 4, with LiteRT-LM, on the GPU or the CPU.

Messages

LiteRT-LM has its own Message and Content classes. _mk_content turns a string, bytes or a Path into the right content type, telling image from audio by the bytes themselves or by the file extension. _mk_msg and _mk_msgs build whole messages from those.

import tempfile
from fastcore.test import test_eq, test_fail
test_eq(_mk_msg("hello").to_json(), {"role": "user", "content": [{"type": "text", "text": "hello"}]})
test_eq(_mk_msg("hi", role="model").to_json()["role"], Role.MODEL.value)
test_eq(_mk_msg("hi", role="assistant").role, Role.MODEL)   # either spelling, whichever litert-lm names it
test_eq([x["role"] for x in _mk_msgs(["a", _mk_msg("b", role="model")])], ["user", Role.MODEL.value])
assert isinstance(_mk_content("x"), Text)
# bytes are sniffed: image vs audio
assert isinstance(_mk_content(b'\x89PNG\r\n\x1a\n' + b'\x00'*16), ImageBytes)
assert isinstance(_mk_content(b'RIFF\x00\x00\x00\x00WAVE' + b'\x00'*16), AudioBytes)

Portable history

rishi’s history is a list of OpenAI-shaped dicts, while LiteRT-LM speaks its own Message objects and calls the assistant model. fmt2hist converts LiteRT-LM messages into history dicts, and hist2fmt converts them back. That is what lets a conversation started here continue on llama.cpp or a hosted model through messages=, and the reverse. Images and audio from earlier turns become [image] and [audio] placeholders on the way into the history.

LiteRT callbacks

Urai’s chats run callbacks at fixed points in a turn. LiteRT-LM needs its own versions of three of them, because the engine keeps the conversation itself. _HistoryCallback copies each message and reply into chat.hist in the shared format. _UsageCallback works out token usage from how much the conversation’s token_count grew during the turn. _ToolReminderCallback appends a short reminder of the available tools to the outgoing message.

Tool calling

LiteRT-LM runs the tool loop inside the engine. The other local backends run it in rishi. The engine calls your Python function and feeds the result back to the model. ChatToolHandler connects that loop to the chat. Before each call it runs the chat’s before_tool_calls callbacks, checks the tool-call budget, and asks the chat’s approve function if there is one. A refused call is recorded with its reason instead of running. The handler writes each call and its result into chat.hist, and runs the after_tool_calls callbacks after each result. Approval itself is described on Urai’s chat page.

Several chats can share one engine. The engine runs one generation at a time. engine_lock returns the single lock of an engine, and a chat holds it for the length of a turn. The chat releases it while a tool runs, and the tool can use the engine. Chats on other threads wait their turn. A second chat on the same thread cannot wait, because the thread that holds the lock would never release it. That chat raises EngineBusy at once.

EngineHold is that hold for one send. Use it as a context manager, or call take and let_go. ChatToolHandler calls let_go while a tool runs and take after it. A chat that already holds the engine on this thread can take it again. recover_context and a one-shot call from a callback do this. The lock is a plain Lock, so closing a stream abandoned on another thread frees the engine. The old name _Hold still works.

Loading models and LitertChat

A .litertlm repo may hold several builds: a portable one, and others made for one kind of hardware, whose names contain -gpu, -npu, -web or an underscore. get_model prefers the portable build. Searches of the repository exclude file names that contain web. An existing model_path bypasses that filter. It finds the file in three steps. It uses a model_path you pass if the file exists. Otherwise it uses a portable build in the local Hugging Face cache. Otherwise it downloads a build, and uses a hardware-specific cached build only when the repo has no portable build or the Hub is unreachable. It raises FileNotFoundError when neither the cache nor the repo has a .litertlm file. cached_model is the cache step on its own. It returns the cached path, or None, without using the network. The old names _get_model and _cached_model still work.

LitertChat.create_engine builds the engine. Unless you name a backend, it tries the GPU first and falls back to the CPU with a warning. Set RISHI_LITERT_GPU=0 to skip the GPU attempt. Pass backend=Backend.GPU() or backend=Backend.CPU() to choose the hardware. On the GPU, activations default to 32-bit floats. With multimodal=True, the default, it also builds the vision and audio encoders that the model file contains. vision_backend and audio_backend choose their hardware, CPU by default. A backend named for an encoder the file lacks gives a warning. cache_dir is the LiteRT-LM cache directory. rishi creates it if it is missing.

think=True turns thinking on. filter_think, on by default, keeps the thought tokens out of the key-value cache (KV cache), where LiteRT-LM stores the keys and values computed for earlier tokens. constrain switches on constrained decoding, which keeps tool calls well formed. It defaults to on when the chat has tools. parallel_tools=True raises NotImplementedError, because the engine’s loop runs one call at a time. If the context window fills during a turn, the chat drops messages from the middle of the history, rebuilds the conversation and sends the turn again. It keeps the first 2 and the last 6 messages. It raises ContextWindowExceededError when nothing can be dropped.

The constants below are the Gemma 4 builds from litert-community.

When the window fills after a tool round, the rebuilt conversation keeps only history from before the turn and the turn message is sent again. A stream closed early cancels the native generation.

# Chats sharing one engine take turns on it (model-free)
import time
from types import SimpleNamespace
def _free(lock):
    "Whether another thread could take `lock` right now."
    out = []
    def _try():
        ok = lock.acquire(blocking=False); out.append(ok)
        if ok: lock.release()
    t = threading.Thread(target=_try); t.start(); t.join()
    return out[0]
def _chat(eng, **kw): return SimpleNamespace(engine=eng, cbs=L(), _budget_exceeded=False, max_steps=None, _steps=0, approve=None, hist=[], tool_max_len=None, **kw)
_eng = SimpleNamespace(); _lk = engine_lock(_eng)
assert engine_lock(_eng) is _lk and _free(_lk)

# Two threads: sends never overlap
_log = []
def _send(ch, tag):
    with EngineHold(ch): _log.append((tag, 'in')); time.sleep(0.05); _log.append((tag, 'out'))
_ts = [threading.Thread(target=_send, args=(_chat(_eng), t)) for t in 'ab']
for t in _ts: t.start()
for t in _ts: t.join()
test_eq([x[1] for x in _log], ['in', 'out', 'in', 'out'])
assert _free(_lk)

# One thread, two streams: the second fails fast instead of hanging the thread that holds the first
def _stream(ch):
    with EngineHold(ch): yield 1; yield 2
_c1, _c2 = _chat(_eng), _chat(_eng)
_a = _stream(_c1); next(_a)
_b = _stream(_c2)
test_fail(lambda: next(_b), contains='mid-turn on this engine')
_a.close(); assert _free(_lk)
test_eq(list(_stream(_c2)), [1, 2]); assert _free(_lk)   # `_b` died with the error; a fresh stream gets in

# A stream abandoned on another thread frees the engine when closed from this one
_box = []
_t = threading.Thread(target=lambda: (_box.append(_stream(_chat(_eng))), next(_box[0]))); _t.start(); _t.join()
assert not _free(_lk)
_box[0].close(); assert _free(_lk)

# An exception mid-stream lets go
def _bad(ch):
    with EngineHold(ch): yield 1; raise ValueError('boom')
_g = _bad(_c1); next(_g); test_fail(lambda: next(_g), contains='boom'); assert _free(_lk)

# The same chat, deeper in its own turn (recover_context, a one-shot from a callback), gets straight in
with EngineHold(_c1):
    with EngineHold(_c1): assert not _free(_lk)
    assert not _free(_lk)
assert _free(_lk)

# The tool loop lets go while a tool runs, so a tool may use the engine, and takes it back for the reply
_ch = _chat(_eng); _ch._hold, _th = EngineHold(_ch), ChatToolHandler(_ch)
with _ch._hold:
    assert not _free(_lk)
    assert _th.approve_tool_call({'function': {'name': 'add', 'arguments': {'a': 2, 'b': 3}}})
    assert _free(_lk)
    with EngineHold(_c2): pass                       # another chat on this thread, from inside the tool
    test_eq(_th.process_tool_response('5'), '5')
    assert not _free(_lk)
assert _free(_lk)
test_eq([m['role'] for m in _ch.hist], ['assistant', 'tool'])
_ch._hold.let_go(); assert _free(_lk)           # letting go twice is harmless

Sharing one engine

A LiteRT-LM Engine lives inside one process, so separate programs cannot attach to it. LitertBroker keeps one in a long-lived process and serves a LitertChat to each client over a Unix socket. Each client has its own conversation and history, and all of them share one copy of the weights. Turns run one at a time, because one engine cannot be driven from two threads at once. The protocol is Urai’s ChatBroker, described on Urai’s broker page.
