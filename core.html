The shared layer

Backend modules import the shared types, such as Chat, ChatOpts and Resp, from urai directly. The tests below check that importing rishi.core registers the runtimes and does not copy Urai’s namespace.

RishiToolLoop is the base class for the backends that drive Urai’s tool loop. These are llama.cpp, MLX, Ollama, the hosted API and Claude Code. Copilot uses it through the hosted API class. LiteRT-LM does not use it, because the LiteRT-LM engine runs tools itself. RishiToolLoop turns on three callbacks by default. UsageCallback counts token usage. ToolReminderCallback reminds the model which tools it has. SlidingWindowCallback removes old messages when the context window is full.

split_model_path turns a model name into a Hugging Face repo id or a local file path. It removes any runtime prefix first. An explicit model_path argument takes priority over a path in the name. The LiteRT-LM, llama.cpp and MLX backends call it. The Ollama backend does not.

import importlib, importlib.util
import rishi, rishi.core, urai

test_eq(rishi.Chat is urai.Chat, True)
test_eq(hasattr(rishi.core, 'Chat'), False)
for mod in ('llama', 'mlx', 'remote', 'claude', 'copilot', 'ollama'):
    if mod == 'mlx' and not importlib.util.find_spec('mlx'): continue   # Apple Silicon only
    public = importlib.import_module(f'rishi.{mod}').__all__
    assert 'Chat' not in public and 'UsageStats' not in public
test_eq(split_model_path(None), (None, None))
test_eq(split_model_path('mlx-community/Qwen3-4B-4bit'), ('mlx-community/Qwen3-4B-4bit', None))
test_eq(split_model_path('mlx/mlx-community/Qwen3-4B-4bit'), ('mlx-community/Qwen3-4B-4bit', None))
test_eq(split_model_path('model.gguf'), (None, 'model.gguf'))
test_eq(split_model_path('repo/id', 'given/path.gguf'), ('repo/id', 'given/path.gguf'))

A SafePyRun patch

Urai runs the Python code that a model writes through SafePyRun. SafePyRun up to version 0.2.6 runs each block of code with separate global and local namespaces. A function defined in the block cannot see a module imported in the same block. For example, import math followed by a function that calls math.sqrt fails with a NameError. rishi replaces the SafePyRun runner with one that uses a single namespace. The replacement can be removed when SafePyRun fixes this.

The host’s __name__ and __builtins__ survive a block that raises or fails to parse:

def _drive(coro):
    try: coro.send(None)
    except StopIteration as e: return e.value

host = {'__name__': 'host', '__builtins__': {}}
for bad in ['raise ValueError', 'def (']: test_fail(lambda: _drive(_rishi_run_python(bad, host)))
test_eq(host['__builtins__'], {})
host['__name__']

Model capabilities

A Caps record lists the kinds of input and output a model takes. You can check it before you send a picture to a model. Urai reads the Caps record of a hosted model from the fastllm model table. Local models have no such table. Each local runtime supplies a function that inspects the model. litert_caps reports text, image and audio for every LiteRT-LM model. LiteRT-LM builds the vision and audio encoders whenever multimodal input is on. ollama_caps_ asks the Ollama daemon, which holds the model weights.

The seven backends

BACKENDS holds one Runtime record per backend. A record has the backend name, the class that implements it, a capabilities function, and the name patterns that identify its models. Urai imports the class when the backend is first used. When Chat gets a model name and no runtime, Urai tries the patterns in list order and takes the first match. Ollama comes before llama.cpp in the list. The id hf.co/unsloth/Qwen3-4B-GGUF contains gguf, but it is an Ollama id and not a file for llama.cpp. LiteRT-LM is the default when no model is named.

Claude Code and Copilot have no patterns, because their model names look like hosted model names. Choose them with a claude/ or copilot/ prefix, or with runtime='claude' or runtime='copilot'. The tests below show which names go to which backend. A name that matches no pattern raises an error.

test_eq(list(RUNTIMES), ['litert', 'ollama', 'llama', 'mlx', 'remote', 'claude', 'copilot'])
test_eq(infer_runtime('gemma-3n-E4B.litertlm'), 'litert')
test_eq(infer_runtime('hf.co/unsloth/Qwen3-4B-GGUF'), 'ollama')   # asked before llama
test_eq(infer_runtime('qwen3-4b-Q4_K_M.gguf'), 'llama')
test_eq(infer_runtime('mlx-community/Qwen3-4B-4bit'), 'mlx')
test_eq(infer_runtime('gpt-5.1'), 'remote')
test_eq(resolve_runtime('claude-sonnet-4.6'), ('remote', 'claude-sonnet-4.6'))
test_eq(resolve_runtime('claude/claude-sonnet-4.6'), ('claude', 'claude-sonnet-4.6'))
test_eq(resolve_runtime()[0], 'litert')                  # nothing named: the default runtime
test_fail(lambda: resolve_runtime('some-unknown-name'), contains="Can't tell which backend")
test_eq(model_caps('gemma-3n-E4B.litertlm').source, 'runtime')
test_eq({'text', 'image'} - set(model_caps('gpt-5.1').inp), set())   # fastllm's table grows, e.g. 'pdf'
test_eq(resolve('gpt-5.1').local, False)
test_eq(resolve('anything.litertlm').local, True)

Compatibility names

Some functions moved from rishi to Urai and got new names. The old names remain as aliases. For example, mk_oai_msg is an alias of mk_msg, and browser_approval is an alias of http_approval. Use Urai’s names in new code, as the rishi backends do.

Installing the skill

The wheel includes a skill.md file that tells a coding agent how to use rishi. mv_skill_md copies it to .agents/skills/rishi/SKILL.md and .claude/skills/rishi/SKILL.md, where agents look for skills. The target root is the dir argument if you pass one. Otherwise it is the root of the current git repository, found by repo_root. Outside a repository, the target root is the current folder. repo_root returns None outside a repository. By default mv_skill_md prints the target paths and copies nothing. Pass dry_run=False to copy. If mv_skill_md finds no skill.md, it returns without output.
