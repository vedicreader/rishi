Messages

fastllm represents a message as Msg(role, content=[Part, ...]). Each part has a type: text, thinking, tool_use, tool_result, input_image or input_audio. An image or audio part holds a data URL in part.text. rishi’s history uses OpenAI-shaped dicts.

to_msg converts one history message to a Msg. to_hist converts a Msg back and returns a list, because one tool Msg can hold several results.

The conversion keeps images and audio as data URLs. It does not replace them with placeholders, so media survives a move between backends. Thinking also survives. rishi stores it in channels['thought'], and fastllm stores it as a thinking part.

When a message mixes text and media, to_hist joins all the text into one part and puts it first. The test below shows this.

Responses and usage

norm_completion converts a fastllm Completion to a rishi Resp. It reads tool calls that the model wrote into its text as <tool_call> tags. It sets truncated when the reply hit the token limit. It adds token usage from norm_usage.

cached_tokens is set when the provider reports prompt caching. reasoning_tokens and cache_creation_tokens appear only when the provider reports them. A local backend’s usage dict does not change.

Some models generate images. fastllm’s message parts describe inputs only. gen_media searches the provider’s raw response for generated images in the shapes that Gemini, the OpenAI Responses and Images APIs, and LiteLLM use. norm_completion stores what it finds in Resp['media'] as {mime, data} dicts. It does not change the text.

RemoteChat

RemoteChat runs fastllm’s async client from synchronous code. It uses Urai’s run_coro and sync_iter. With no model named, it uses dflt_remote, which is gpt-5.1.

max_output_tokens sets the output cap. Without it, the cap is the maximum that fastllm’s model table gives for the model. For a model that is not in the table, the cap is DFLT_MAX_TOKENS, 16,000. A reasoning model spends its thinking from the same cap. A small cap cut its tool calls short.

These options exist only on RemoteChat:

  • tool_choice forces one tool. The value 'required' forces any tool.
  • effort sets the provider’s reasoning effort. reasoning_effort is an accepted alias.
  • tool_mode='native' is the default. It sends tool schemas in the API’s tools field.
  • tool_mode='tags' writes the tool schemas into the system prompt and reads <tool_call> tags from the reply. Use it for a provider that has no tools field.
  • vendor_name and api_name override the vendor and the API that fastllm infers from the model id.

You can pass tool_mode for a single turn, streamed or not.

When the provider’s API lacks the effort level you set, the chat sends the level that EFFORT_MAP names. max becomes xhigh on OpenAI and Azure. xhigh and max become high on Gemini.

When a provider refuses the effort with a 400, the chat repeats the call once without it. dropped_effort then holds the reason, and the chat sends no effort. Set dropped_effort back to None to send effort again.

A one-shot call with think=False asks for NO_THINK_EFFORT, which is 'minimal'.

You can name a Gemini model with or without models/, as in gemini-3.5-flash, gemini/gemini-3.5-flash or models/gemini-3.5-flash. Gemini’s API puts the model in the URL and answers 404 without that prefix. The chat adds the prefix to the request. model_id stays as you gave it.

Some providers run tools on their own side, such as web search. Those calls come back marked server=True. The chat records them in the history. rishi does not run them.

A vendor in STREAM_ONLY answers only streamed requests. At present the only such vendor is codex. For it, the chat streams every request and collects the result.

Azure OpenAI’s v1 API works through base_url. Set these values:

  • base_url: https://<resource>.openai.azure.com/openai/v1
  • model: the deployment name
  • api_key: the Azure key
  • api_name='openai' for the Responses API

The chat sends no api-version. The v1 API needs none.

On the chat-completions route, api_name='openai_chat', an Azure reasoning deployment refuses max_tokens. For a host in MAX_COMPLETION_HOSTS, the chat sends the output cap as max_completion_tokens. Every Azure model accepts that field.

A tool call that does not decode

fastllm decodes a model’s tool-call arguments before rishi sees the reply. It raises JSONDecodeError when the arguments are not whole JSON. The usual cause is the output cap: the model ran out of tokens while it wrote the call.

args_error checks that the error came from one of the fastllm functions in ARG_SITES. rishi raises any other decode error unchanged. cut_args tells a cut-off call from a malformed one.

A cut-off call goes back to the model with urai’s cut_msg_. The next step runs at CUT_CAP_MULT times the cap, up to the most that fastllm says the model can write. A malformed call goes back with the decoder’s error message.

A reply cut off while the model was still thinking, with no text and no call, goes back the same way and uses the same single resend. A second failure in the turn raises ToolCallError with the reason.

# a tool call cut off at the output cap, or not JSON at all, goes back to the model rather than killing the turn
# with fastllm's bare `JSONDecodeError`; the step after a cut-off call gets `CUT_CAP_MULT` times the cap
import fastllm.acomplete as fa
from fastcore.xtras import dict2obj
from urai import cut_msg_
def _wf(path: str, content: str) -> str:
    'Write content to path.'
    return f'wrote {len(content)}'
_CUT, _BAD, _OK = '{"path": "a.txt", "content": "it stops', '{"path": "a.txt" "content": "x"}', '{"path": "a.txt", "content": "whole"}'
def _resp(args):    # a Responses reply, its call cut short when `args` is
    if args is None: return {'output': [{'type': 'message', 'role': 'assistant', 'content': [{'type': 'output_text', 'text': 'done'}]}], 'status': 'completed',
                             'usage': {'input_tokens': 5, 'output_tokens': 1, 'total_tokens': 6}}
    return {'output': [{'type': 'function_call', 'call_id': 'c1', 'id': 'fc1', 'name': '_wf', 'arguments': args}],
            'usage': {'input_tokens': 5, 'output_tokens': 9, 'total_tokens': 14}, 'status': 'incomplete' if args == _CUT else 'completed'}
def _cc(args):      # a chat-completions reply
    m = {'role': 'assistant', 'content': 'done'} if args is None else {'role': 'assistant', 'content': None, 'tool_calls': [{'id': 'c1', 'type': 'function', 'function': {'name': '_wf', 'arguments': args}}]}
    return {'choices': [{'index': 0, 'message': m, 'finish_reason': 'stop' if args is None else 'length' if args == _CUT else 'tool_calls'}],
            'usage': {'prompt_tokens': 5, 'completion_tokens': 9, 'total_tokens': 14}}
def _chunks(args):  # a chat-completions stream: some prose, then the call in pieces, then `length` when it was cut
    yield {'choices': [{'index': 0, 'delta': {'role': 'assistant', 'content': 'Writing it.'}}]}
    if args is None: yield {'choices': [{'index': 0, 'delta': {}, 'finish_reason': 'stop'}]}; return
    for i in range(0, len(args), 8):
        f = {'arguments': args[i:i+8]} | ({'name': '_wf'} if not i else {})
        yield {'choices': [{'index': 0, 'delta': {'tool_calls': [{'index': 0, 'id': 'c1' if not i else None, 'type': 'function', 'function': f}]}}]}
    yield {'choices': [{'index': 0, 'delta': {}, 'finish_reason': 'length' if args == _CUT else 'tool_calls'}]}
def _wire(*script):
    "A fake `provider_req` answering with `script` in order, and the request bodies it saw."
    bodies, it = [], iter(script)
    async def req(cli, path, body, params=None, stream=False, **kw):
        bodies.append(body); a = next(it)
        if isinstance(a, Exception): raise a
        if not stream: return dict2obj((_cc if 'chat' in path else _resp)(a))
        async def ev():
            for c in _chunks(a): yield dict2obj(c)
        return ev()
    return req, bodies
def _run(chat, *script, stream=False):
    req, bodies = _wire(*script)
    _req, fa.provider_req = fa.provider_req, req
    try: r = chat('go', stream=stream); r = ''.join(r) if stream else r
    finally: fa.provider_req = _req
    return r, bodies
_resps = lambda **kw: RemoteChat('gpt-5.4', api_key='k', tools=[_wf], max_output_tokens=1000, **kw)
_chats = lambda **kw: RemoteChat('gpt-5.4', base_url='https://x.example.com/v1', api_key='k', api_name='openai_chat', tools=[_wf], max_output_tokens=1000, **kw)
caps = lambda bodies: [b.get('max_output_tokens') or b.get('max_tokens') or b.get('max_completion_tokens') for b in bodies]

# cut off, then asked again at four times the cap, then whole: the call runs, on both wires and both ways of sending
for mk, stream in ((_resps, False), (_resps, True), (_chats, False), (_chats, True)):
    if mk is _resps and stream: continue           # the Responses stream is fastllm's, covered by its own event parser
    c = mk()
    r, bodies = _run(c, _CUT, _OK, None, stream=stream)
    test_eq([m['role'] for m in c.hist], ['user', 'assistant', 'user', 'assistant', 'tool', 'assistant'])
    test_eq((c.hist[2]['content'], c.hist[4]['content']), (cut_msg_, 'wrote 5'))
    test_eq(caps(bodies), [1000, 4000, 1000])        # the raise lasts one step
    assert ('Writing it.' if stream else 'cut off at its 1000-token output limit') in c.hist[1]['content'] and 'lost' not in c.hist[1]   # what streamed, else why

# cut off twice: `ToolCallError` says what happened, not a decoder message
for mk, stream in ((_resps, False), (_chats, True)):
    test_fail(lambda: _run(mk(), _CUT, _CUT, stream=stream), contains="gpt-5.4's tool call was cut off at its 4000-token output limit")

# arguments that are not JSON go back naming the problem, at the same cap
c = _chats()
r, bodies = _run(c, _BAD, _OK, None, stream=True)
assert "not valid JSON (Expecting ',' delimiter at char 17)" in c.hist[2]['content']
test_eq((c.hist[4]['content'], caps(bodies)), ('wrote 5', [1000, 1000, 1000]))

# a reply that is all thinking when the cap cuts it goes back once at the raised cap, then raises
_THINK = 'think'
_r0, _c0 = _resp, _chunks
def _resp(args):
    if args != _THINK: return _r0(args)
    return {'output': [{'type': 'reasoning', 'id': 'r1', 'summary': []}], 'status': 'incomplete', 'incomplete_details': {'reason': 'max_output_tokens'},
            'usage': {'input_tokens': 5, 'output_tokens': 1000, 'total_tokens': 1005}}
def _chunks(args):
    if args != _THINK: yield from _c0(args); return
    yield {'choices': [{'index': 0, 'delta': {'role': 'assistant', 'content': ''}}]}
    yield {'choices': [{'index': 0, 'delta': {}, 'finish_reason': 'length'}]}
