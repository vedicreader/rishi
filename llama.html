Loading GGUF models

You name a model by its Hub repo id, such as Qwen/Qwen3-4B-GGUF, and rishi picks the file. The constants below are ready-made repo ids. Qwen3 models can think before answering and write tool calls in a format llama.cpp already parses. Any GGUF repo works.

A repo often holds one file per quantization, plus an mmproj file. That file is the projector, a small separate model that turns images or audio into input the language model can read. get_model finds the model file in three steps. It uses a model_path you pass if the file exists. Otherwise it searches the local Hugging Face cache without using the network. Otherwise it downloads the file. It prefers the quant you ask for, Q4_K_M by default, and falls back to the first .gguf file. It never picks the projector. It raises FileNotFoundError when the repo has no model file. cached_model is the cache step on its own and returns None on a miss. The old names _get_model and _cached_model still work. get_mmproj finds the projector the same way, for vision and audio models. It raises FileNotFoundError when the repo has no projector. DFLT_N_CTX is the context window an engine gets when nothing else sets one, 8192 tokens.

gpu_offload_supported says whether the installed llama-cpp-python wheel was built with Metal or CUDA. A CPU-only wheel ignores n_gpu_layers.

Audio

llama.cpp reads images and audio through its mtmd library, but llama-cpp-python’s MTMDChatHandler only passes images to it. rishi patches four of the handler’s methods so that audio takes the same route:

  • get_image_urls collects input_audio parts as well as images, in the order they appear.
  • _get_template_messages replaces each image or audio part with a marker. When only text parts remain, it joins them into one string. Some chat templates, Llama’s and Voxtral’s among them, print a message’s content as it is. Without the join they would print a Python list.
  • _create_bitmap_from_bytes decodes audio with read_audio and hands the samples to mtmd_bitmap_init_from_audio. Images take the original path.
  • _init_mtmd_context lets a projector with an audio encoder and no vision encoder load, where upstream raises an error.

read_audio decodes any format libsndfile reads, including WAV, FLAC, OGG and MP3. It mixes stereo down to mono and resamples to sr Hz, 16000 by default. The patched _create_bitmap_from_bytes passes the sample rate the projector reports, and falls back to 16000 when the projector reports none. The tests below run it on the 24-second speech.wav and on generated tones, and pass the result to the real llama.cpp C function.

LlamaChat

LlamaChat(model) loads the model once and keeps it for the life of the chat. create_engine builds the llama_cpp.Llama object and adds the multimodal handler when mmproj is set. Pass mmproj=True to fetch the projector from the same repo, or a path to use your own.

The options particular to llama.cpp are quant, the quantization to download; n_gpu_layers, how many layers go on the GPU, where 0 (the default) keeps everything on the CPU; and mmproj. think=True or think=False writes Qwen’s /think or /no_think switch into the system prompt. To share one loaded model between chats, build it once with create_engine and pass it to each as engine=. close releases an engine the chat built itself and leaves a shared engine= open.

The KV cache

While a model reads a prompt, it computes a key and a value for every token, and llama.cpp keeps them in the KV cache. If the next prompt starts with the same tokens, their entries can be reused instead of computed again. Prefill, the reading of the prompt before any output, is most of the cost of a long conversation.

rishi reuses the cache by keeping one Llama object across turns. Llama.generate compares each new prompt with the tokens already in its context, trims the cache back to the longest common prefix, and evaluates only what follows. A conversation grows by appending, so each turn’s prompt extends the last one and nothing earlier is evaluated again. The manual example below shows it: on the second turn llama.cpp evaluated 28 new tokens and reused 315.

Three things break the prefix, and cached_tokens takes all three into account:

  • A one-shot call on the same engine. A Llama has a single context, so classify, structured, check and grades overwrite the conversation in it, and the next real turn starts from scratch. Two chats sharing one engine=, or a judge chat on the same engine, have the same effect. With preserve_cache=True the chat saves the llama state before a one-shot and restores it afterwards. That copies the whole cache. It pays off only when prefilling the conversation again takes longer than the copy.
  • A rewritten history. When SlidingWindowCallback drops old messages, or context recovery shortens the history, everything after the first changed message is evaluated again.
  • Media. The turn that carries an image or audio clip sends the real thing. On later turns an [image] or [audio] placeholder replaces it, and llama.cpp does not encode it again. The replacement changes the prompt from that message on. The turn after a media turn evaluates again from there.

save_cache writes the whole context to a file, and load_cache reads it back into a chat built on the same model. The method names match rishi.mlx. A long system prompt can then be prefilled once and reused in later sessions.

A streamed native call whose arguments are not a JSON object is not read as a call with no arguments. _stream_step marks the call unread and sets tool_parse_failed, so the tool loop asks the model to send it again, and the stored call renders into the next prompt as an empty argument object.

class _SEng:
    n_tokens = 5
    def create_chat_completion(self, msgs, **kw):
        d = lambda tc: {'choices': [{'delta': {'tool_calls': tc}, 'finish_reason': None}]}
        yield d([{'index': 0, 'id': 'a', 'function': {'name': 'add', 'arguments': '{"a": 1'}}])
        yield d([{'index': 1, 'id': 'b', 'function': {'name': 'add', 'arguments': '{"a": 1, "b": 2}'}}])
        yield {'choices': [{'delta': {}, 'finish_reason': 'tool_calls'}]}

c = LlamaChat.__new__(LlamaChat)
c.engine, c._samp, c.max_output_tokens, c.toolspecs = _SEng(), {}, None, []
c.comp_kw, c.turn_msg, c._sys_msgs, c._cache_dirty, c.hist = {}, None, lambda: [], True, []
c.count_tokens, c._note_cache = (lambda t: 0), (lambda u, cached: u)

Examples (manual)

These cells load real weights and are marked #| eval: false. The test run skips them. The output shown was saved from an earlier run. For ordinary chat, tools, streaming, classification and structured output, use the calls on the index page with a -GGUF repo id. The examples here show what only this backend does: reusing the KV cache, and image and audio input through mmproj.

The first example counts the tokens llama.cpp evaluates on each turn. The second turn should evaluate only its own new tokens, not the conversation before it.

# Real llama.cpp KV-prefix test: instrument `eval` to see how many tokens are actually evaluated.
# On turn two the first eval batch should contain only the new tail, not the cached conversation.
kvchat = LlamaChat(qwen3_06b, think=False, temp=0.0, max_output_tokens=16)
seen, orig_eval = [], kvchat.engine.eval
def counted_eval(tokens):
    seen.append(len(tokens))
    return orig_eval(tokens)
kvchat.engine.eval = counted_eval
try:
    kvchat(('cache verification context ' * 96) + '\nReply with exactly: stored')
    context_before_turn2 = kvchat.engine.n_tokens
    seen.clear()
    r = kvchat('What exact word did I ask you to reply with? Reply with only that word.')
    assert seen, 'llama.cpp never evaluated the second prompt'
    second_tail = seen[0]
    print(dict(context_before_turn2=context_before_turn2, second_tail_evaluated=second_tail,
               reported_cached=kvchat.use.cached_tokens, answer=resp_text(r)))
    assert second_tail < context_before_turn2, 'turn two re-evaluated the full prior context; KV prefix reuse missed'
    assert kvchat.use.cached_tokens > 0, kvchat.use
    assert 'stored' in resp_text(r).lower(), resp_text(r)
finally:
    kvchat.engine.eval = orig_eval
    kvchat.close()

Streaming and thinking

stream=True yields markdown as on every backend, with the model’s thinking as a blockquote and each tool call as a line starting with ⏳. Urai’s display_stream renders it live in a notebook, as on the LiteRT-LM backend. With a Qwen3 model, think=True turns thinking on.

Stopping with an LLM judge

When a model writes Python code blocks for Urai to run, Urai’s PyFenceCallback runs each block and shows the model the output. It repeats this until its done(chat) function returns True or the model writes no more code. output_matches(expected) builds a done that stops once the last code output contains expected. task_complete asks the model instead, through chat.classify, whether the conversation has done what was asked. done can be any function that takes the chat and returns a bool, including one that consults a second, stronger chat. Both helpers live in urai.sandbox and work with every backend; see Urai’s sandbox page.

Sharing one engine

A loaded Llama belongs to one process, and loading the same model in several programs wastes memory. LlamaBroker loads it once in a long-lived process and serves it over a Unix socket. Each client gets its own LlamaChat and history, and all of them share one copy of the weights. The protocol and the client are Urai’s ChatBroker, described on Urai’s broker page.
